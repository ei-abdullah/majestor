How Majestor's Dependencies Are Running? It's the Containers.

Yes, I install and run my dependencies using a docker-compose.yml file and wire them up in my application.yml file. Done. 👍

Wait, let me tell you how I do it. Right now, the only dependency is a database. My backend service uses PostgreSQL, and here's the crazy part—even for development, I don't have PostgreSQL installed on my PC. I use Docker.

It goes like this: I have a docker-compose.yml file (you can name it docker.yml, compose.yml, or whatever floats your boat). I list all the dependencies in that file. You can add as many as you like—be it a web server like NGINX or Apache, another server container (e.g., another Spring Boot or Node.js server), a database container, or a streaming service like Apache Kafka or RabbitMQ.
My app only uses a database. Simply a skill issue, I would say.

Below is a snapshot of my compose file, and I run this command: docker compose up -d

What this command means: docker compose up reads all the contents from my docker-compose.yml file and spins up a container. It installs all the dependencies as images (if not already installed) and adds those dependencies into the container. The -d flag runs it in detached mode, meaning it runs in the background so your terminal stays free.

Then you simply wire it up using the credentials set in the docker-compose.yml file. 

Bonus tip: If the .env file is in the current directory, Docker Compose automatically picks up the environment variables so no need to load them into the system or even at the project level. It just works.
